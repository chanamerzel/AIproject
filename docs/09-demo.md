# 09 — תסריט הצגה למרצה

זמן: 8–10 דקות הדגמה, ואחריה שאלות.  
לכל שלב: **מה פותחים / לוחצים**, **מה אומרים**, ו**איזו דרישה זה מוכיח** (מזהים מ-[01-requirements.md](01-requirements.md)).

## כללי ברזל

1. **הערכה חיה אחת בלבד.** למכסה החינמית של Gemini יש כ-20 בקשות ביום לכל מודל, והערכה אחת צורכת כ-12. ההגשה החיה של המועמד בשלב 4 היא ההערכה היחידה.
2. **מועמדות מוכנה מראש.** הדוח המלא מוצג על מועמדות שכבר הוערכה (Dana Candidate, משרת Python Backend), ולא תלוי בהרצה החיה.
3. **כל עמוד נטען לאט.** נמדד ברשת הזו: כניסה + דשבורד כ-40 שניות, דף מועמדות כ-15 שניות, `/health` כ-14 שניות. לכן פותחים טאבים מראש, ובזמן הטעינה מדברים.
4. **אין "בטל".** כל פעולה היא אירוע שנשמר לתמיד (Event Sourcing). לפני השיעור **לא** מתרגלים: הגשה עם `cand2@fit.local`, החלטה על המועמדות של Dana, הערכה חוזרת, ואישור המשרה Frontend Developer.

## 6. הכנה לשאלות

**1. למה Somee?**  
מומלץ בהוראות הקורס (NFR-5, NFR-8), חינמי, ו-SQL נותן סדר קבוע וכתיבה אטומית, וזה מה שיומן אירועים צריך. Azure דורש כרטיס אשראי, ו-MongoDB חלש בטרנזקציות. (D2 ב-[08-decisions.md](08-decisions.md))

**2. למה Event Sourcing ולא סתם לעדכן טבלה?**  
כל שינוי נשמר כאירוע עם גרסה, מי עשה ומתי. כך יש היסטוריית הערכות מלאה (F10), ציר זמן לכל מועמדות, ואפשר לבנות את כל הטבלאות מחדש מהיומן (`app.replay`). הטבלאות מתעדכנות מיד אחרי כתיבת האירוע, כדי שהמשתמש יראה את השינוי בלי עיכוב. (D5, D6)

**3. מה ההבדל בין Command ל-Query אצלך?**  
Command נמצא ב-`app/commands/`: בודק, כותב אירוע, והאירוע מעדכן טבלה דרך `app/projections.py`. Query נמצא ב-`app/queries/` ורק עושה SELECT. יש בדיקה אוטומטית (`tests/test_architecture.py`) שמוודאת ש-Query לא כותב אירועים.

**4. למה הסוכן בתהליך נפרד?**  
ההוראות דורשות תהליך עצמאי שקורא מהמסד. הערכה לוקחת דקות (רשת, RAG, מודל שפה), ובתוך בקשת דפדפן המשתמש היה נתקע. ה-worker קורא את המסד כל 20 שניות, בלי Celery או Redis. (D15)

**5. מה אם המודל ממציא ציונים?**  
הפונקציה `_finalize` מצליבה את הדוח מול מה שהכלים באמת החזירו: כיסוי הדרישות וההתאמה הסמנטית נלקחים מהכלים, והציון הכולל וההמלצה מחושבים מחדש בנוסחה. כלי חובה שאף סוכן לא הפעיל מופעל בכוח ונרשם ב-`tools_skipped_by_agent`. קישורים שהמודל כתב ו-Tavily לא החזיר נזרקים. אם המודל החזיר JSON שבור, הכול מחושב מהכלים ומסומן `agent_report_valid=false`. הרכיב היחיד שבא משיקול המודל הוא ציון ראיות הרשת (20%), והוא מוגבל לטווח 0–100.

**6. למה Gemini ראשון ו-Ollama גיבוי?**  
Gemini מסיים הערכה בדקה עד שלוש. Ollama על המחשב הזה (בלי כרטיס מסך) לוקח כ-12 דקות. במצב `auto` המערכת מנסה כמה מודלי Gemini לפי הסדר, ואם המכסה נגמרה או אין אינטרנט עוברת לבד ל-Ollama. רואים את זה בהיסטוריה: הרצה אחת ב-Ollama ושתיים ב-Gemini. (D11)

**7. איך עובד החיפוש הסמנטי?**  
כל קורות חיים הופכים לווקטור של 384 מספרים במודל all-MiniLM-L6-v2, שרץ מקומית בלי מפתח. הווקטורים נשמרים ב-Chroma גם כמסמך שלם (לדירוג) וגם כקטעים של כ-700 תווים (לציטוטים ב-RAG). תיאור המשרה הופך לווקטור, ומחפשים את הקרובים ביותר עם סינון לפי משרה. נמדד: CV מתאים 0.62 מול CV לא קשור 0.06. (D7, D8)

**8. מה זה MCP?**  
פרוטוקול סטנדרטי שבו סוכן קורא לכלים חיצוניים. המערכת מפעילה את שרת הכלים כתהליך ומדברת איתו ב-JSON-RPC דרך stdio. כך נקראים גם שני הכלים שלי (`python -m mcp_studio`) וגם Tavily (`tavily-mcp`), ולא דרך import או REST ישיר. (`agent/mcp_client.py`)

**9. מה עושים שני הכלים ב-MCP Studio?**  
`extract_resume_profile`: מחלץ מקורות החיים כישורים (מתוך רשימה קבועה), שנות ניסיון, מעסיק אחרון ומייל. `evaluate_requirement_coverage`: בודק כמה מכישורי החובה מופיעים ב-CV, ומוריד 15 נקודות אם אין מספיק שנות ניסיון. שניהם קבועים ודטרמיניסטיים, ולכן נבדקים בבדיקות ומשמשים מקור לציונים. (D14)

**10. מה זה Deep Agent, ובמה הוא שונה מסוכן רגיל?**  
ספריית `deepagents` של LangChain. הסוכן הראשי כותב תוכנית (`write_todos`) ומאציל משימות (`task`) לתתי-סוכנים, ולכל אחד יש כלים משלו והקשר נפרד. בדוח רואים בטבלה איזה תת-סוכן הפעיל איזה כלי. (D9, D10)

**11. איך נאכפות ההרשאות?**  
כל נתיב רגיש מוגן ב-`role_required` מ-`app/security.py`, והשרת מחזיר "אין הרשאה" גם אם מסתירים כפתור וגם אם שולחים את הבקשה ידנית. מועמד לא מקבל את דוח הסוכן מהשרת, ולא יכול לפתוח מועמדות של מישהו אחר. הסיסמאות שמורות כ-hash. (D17)

**12. איך הבדיקות רצות ב-CI מול SQL Server?**  
ב-GitHub Actions מרימים שרת SQL Server 2022 כ-service, יוצרים מסד בדיקות, ומריצים את כל הסוויטה עם `TEST_DATABASE_URL`. הבדיקות רצות בלי אינטרנט: הטמעות מדומות, הסוכן במצב `pipeline` (אותם כלים בלי מודל שפה), ובדיקה נפרדת מריצה את ה-Deep Agent עם מודל מתוסרט. (D20, [06-testing.md](06-testing.md))

**13. מה קורה אם הסוכן נכשל?**  
נכתב אירוע `ApplicationScreeningFailed` והמועמדות חוזרת לתור. אחרי 3 כישלונות הסטטוס **הערכה נכשלה** ו-HR רואה את השגיאה. בקשת הערכה חוזרת נותנת 3 ניסיונות חדשים. אם אין אף מודל שפה זמין, ה-worker לא מעריך בכלל ולא ממציא ציון.

**14. איפה נשמרים קורות החיים?**  
הקובץ נשמר בתיקיית `uploads` (volume של Docker), הטקסט נשמר באירוע `ApplicationSubmitted` ובטבלת המועמדויות, והווקטורים ב-Chroma. Chroma מקומי ולא בענן, כי הדרישה היא חיפוש סמנטי ולא ענן. (D7)

**15. איך השתמשת ב-AI בפיתוח?**  
לפי SDAD: קודם מסמכי `docs/`, אחר כך `AGENTS.md`, Rule ו-Skills שמכריחים את סוכן הקוד לעבוד לפי CQRS ו-Event Sourcing, ואז פיצ'ר שלם בכל פעם עם בדיקה. ה-CI מוודא שכלום לא נשבר.

### Somee לא זמין (האינטרנט עובד)

`/health` מחזיר `"status": "error"`. עוברים ל-SQLite מקומי:

1. ב-Cursor פותחים את `.env` **לא על המקרן**, ומוסיפים `#` בתחילת השורה `DATABASE_URL=...` (לא מוחקים, כדי לא לאבד את הסיסמה).
2. בטרמינל:

```powershell
docker compose up -d
docker compose exec web python seed_demo.py
```

3. `/health` מציג `"backend": "sqlite"`.

זה עובד כי ב-`docker-compose.yml` מוגדר `DATABASE_URL: ${DATABASE_URL:-sqlite:////app/data/fitscreen.db}`: אם המשתנה ריק או חסר, המערכת משתמשת בקובץ SQLite בתוך volume של Docker. זה מסד נפרד, ולכן אין בו את Dana ואת ההיסטוריה. ההגשה החיה תהיה ההערכה היחידה שתוצג. אומרים למרצה: "Somee לא זמין כרגע, אז עברתי למסד המקומי. זה אותו קוד, רק כתובת חיבור אחרת."  
חזרה ל-Somee: מוחקים את ה-`#` ומריצים `docker compose up -d`.

### אין אינטרנט בכלל (או שהסינון חוסם)

1. קודם מנסים נקודה חמה מהטלפון.
2. אם אין ברירה: SQLite כמו בסעיף הקודם, ובנוסף מוסיפים ל-`.env` שורה `LLM_PROVIDER=ollama` (או משנים אותה אם כבר קיימת), ואז `docker compose up -d`.
   - ההערכה תרוץ ב-Ollama כ-12 דקות, לכן מגישים מועמדות מיד בתחילת ההצגה.
   - Tavily לא יעבוד. הדוח יציין שאימות הרשת לא הושלם, והציון יחושב רק מכיסוי דרישות והתאמה סמנטית.
   - העיצוב (Bootstrap) והגרפים (Chart.js) נטענים מהאינטרנט, ולכן המסכים יופיעו בלי עיצוב ובלי גרפים, אבל כל הכפתורים יעבדו.
3. אחרי ההצגה: מחזירים את `.env` למצב הקודם ומריצים `docker compose up -d`.
